# Wayfinder Loop

A calm, inspectable travel-planning agent built with React and TypeScript. It turns a destination, dates, budget, and preferences into a budget-aware day-by-day itinerary while exposing the complete tool-calling loop in the UI.

## What is included

- Explicit agent loop with plan → tool call → structured result → replan/clarification → final validation states.
- Five deterministic tools: `weather_lookup`, `flight_price_lookup`, `lodging_lookup`, `attractions_lookup`, and `calendar_day_planner`.
- Graceful termination when a tool receives bad input, returns no results, or the assembled itinerary exceeds the budget.
- Strict boundary validation for destination, ISO dates, chronological order, positive budgets, and supported 2–7 calendar-day trips.
- Lodging nights are always `calendar days - 1`, and the itinerary enforces that relationship before returning.
- Structured TypeScript output types for forecasts, flight options, lodging, activities, itinerary days, and trace events.
- Two complete successful demo traces in `traces/successful-runs.json`, generated by the same agent implementation used by the UI and selectable from the app.
- Expandable JSON payloads for every event in the technical trace panel.

## Architecture

```text
src/pages/Index.tsx
  ├── PlannerForm             request controls
  ├── ItineraryView           structured final output
  └── TracePanel              inspectable event timeline

src/agent/travel-agent.ts
  ├── weatherLookup
  ├── flightPriceLookup
  ├── lodgingLookup
  ├── attractionsLookup
  ├── assembleItinerary
  └── runTravelAgent          explicit bounded loop

src/data/demo-traces.ts        two successful runs generated from the same agent
traces/successful-runs.json     committed full event logs for both successful runs
```

The provider implementations are deterministic mocks so the demo is repeatable and can run offline. Each tool still has a real input/output boundary, explicit error result, and a trace event. The execution plan is a bounded `for...of` loop: each tool call is logged immediately before execution and its result immediately after; a structured failure ends the loop with a replan/clarification event rather than inventing data. Replacing a tool with a live provider only requires changing its implementation while keeping the agent contract intact.

## Setup

This is a Vite React app.

```text
npm install
npm run dev
```

The production build uses `npm run build`.

## Example input

```json
{
  "destination": "Lisbon",
  "startDate": "2025-09-12",
  "endDate": "2025-09-15",
  "budget": 2200,
  "preferences": {
    "pace": "slow",
    "interests": ["local culture", "food"],
    "dietary": "Vegetarian"
  }
}
```

A successful run returns an `Itinerary` with flights, lodging, weather, daily activities, totals, and planning notes. Try `Nowhere` or a very small budget in the UI to see the loop stop safely after a replan and clarification event.

## Two successful run traces

Both traces below are full deterministic traces generated by `runTravelAgent` and committed as `traces/successful-runs.json`; the UI also exposes them through `DEMO_TRACES`. The UI lets you switch between them and expand each structured input/output payload.

### Run 01 — Lisbon · slow culture

- Input: Lisbon · Sep 12–15, 2025 · `$2,200` · slow · local culture + food · vegetarian
- Loop: request → plan → weather lookup → flight lookup → lodging lookup → attractions lookup → day planner → final validation
- Result: 4 itinerary days, Casa do Pátio, TAP Air Portugal, estimated total `$1,054`

### Run 02 — Kyoto · balanced craft

- Input: Kyoto · Oct 3–7, 2025 · `$2,600` · balanced · heritage + nature · vegetarian
- Loop: request → plan → weather lookup → flight lookup → lodging lookup → attractions lookup → day planner → final validation
- Result: 5 itinerary days, The Juniper House, Northstar Air, estimated total `$1,640`

To inspect every event (including the exact inputs and structured outputs), open the app's **Technical trace** section or inspect `traces/successful-runs.json`.
